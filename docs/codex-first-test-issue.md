# Codex往復テスト用 Issue案（初回・小さいもの）

作成日：2026-11-23
目的：フィリップ⇔Codex（GitHub＋Codexクラウド方式）の往復が動くかを確認する、最小のテスト。
出品・販売はしない。テストのみ。

## 前提（守ること）

- 対象は副業関連のみ。課金なし（APIキー方式は不採用）。
- 勤務先の資料・取引先名・実数値・内部手順は使わない。一般知識＋ダミーデータのみ。
- ステージ0の範囲：Googleスプレッドシートの関数・シート設計のみ。GASなし、VBAなし。
- 却下済みの結論（Excel VBA受託、GPTs、チャットボット等）を蒸し返さない。
  詳細は `side-business-context-for-codex.md` を参照。

## Issueタイトル案

[テスト] 在庫・発注管理テンプレ（関数・シート設計のみ、ダミーデータ10件）

## Issue本文案（Codexへ出す文面）

```
目的：スプレッドシートで使える在庫・発注管理テンプレの試作。動作確認が目的で、販売はしない。

作るもの（templates/inventory-order/ 配下）：
1. 商品マスタ（10件、ダミーデータ）：商品名、単価、発注点、安全在庫、リードタイム日数
2. 在庫台帳：商品名、現在庫、発注残、入庫予定日
3. 発注リスト：商品名、現在庫、発注点、発注要否、発注数量
   - 発注要否は関数で判定すること（現在庫＋発注残 ＜ 発注点 なら「要」）
   - 発注数量は関数で計算すること（MAX(0, 発注点 − 現在庫 − 発注残)）
   - 結果を値で直書きしないこと
4. SPEC.md：各シートの列定義と使った関数の式を日本語で列挙
5. 上記3シートを1つの .xlsx にしたもの（関数は値ではなく式のまま入れること）

制約：
- ダミーデータのみ。実在の会社・取引先・実数値は入れない
- GAS・VBA・マクロは使わない
- 日本語の列名にすること
- 外部リンク・個人情報は入れない

完了条件：
- .xlsx を Googleスプレッドシートで開き、在庫数を変えると発注要否と発注数量が連動して変わる
- SPEC.md の式と .xlsx の式が一致する
- ダミー10件すべてに発注要否が出る
```

## フィリップ側の検証（CodexのPRが出た後）

1. PRの差分を読む（ファイル構成・式・ダミーデータの確認）
2. .xlsx を開いて在庫数を変え、発注要否・数量が連動するか確認
3. 問題があれば `@codex` で修正を1回だけ回す
4. 結果をKakiに報告する（出品・公開はKakiの判断なしにしない）

## まだKaki側で残っていること

1. chatgpt.com/codex が開けるか（Codexクラウドが使えるプランかの確認）
2. GitHubで副業用リポジトリ（なければ対象アカウント）を選択する
   - 選択用リンク：https://github.com/apps/meta-muse-ai/installations/new
   - 選択後、フィリップがアクセスを確認する
